### B.4 Fate of jpatch / JPatcht — the `jptch` question

- `src/jpatch.cpp` is **gone** at 0.8.5 (removed upstream in a1e87f4 "084b", 2020-09-01). Patch application moved into the jdiff binary itself as **`JPatcht`** (a class, not a standalone program): 85:JPatcht.h:34-49 (`class JPatcht { JPatcht(JFile &apFilOrg, JFile &apFilPch, JFileOut &apFilOut, const int aiVerbse=0); int jpatch(); ... }`).
- **The 0.8.5 `jdiff` binary applies patches** in three ways:
  1. `jdiff -u <source> <patchfile> [<dest>]` — option `-u`/`--undiff` (85:main.cpp:385-387 sets `liFun=Patch`; execution at 85:871-876: `JFileOut loFilOut(lpFilOut); JPatcht loJPatcht(*lpJflOrg, *lpJflNew, loFilOut, liVerbse); liRet = loJPatcht.jpatch();`).
  2. **argv[0] dispatch** (85:main.cpp:303-315): binary basename starting `jpatch` → Patch function, `jdedup` → Dedup, `jtst` → Test. Verified live: `ln -s jdiff ./jpatch; ./jpatch src patch > out` restores correctly (exit 0).
  3. `-t`/`--test[=n]` sets Test mode (both diff and patch phases) — **broken**, see §G-new.
- JPatcht I/O is via the same JFile input stack (patch file opened as `JFileAheadIStream`/`JFileAheadStdio` with 1MB default buffers) and `JFileOut` (85:JFileOut.cpp:28-84, wraps a `FILE*`, `putc` + `copyfrom(JFile&,pos,len)` using `getbuf` fast path).
- Verdict for the Rust port's `jptch` binary: **upstream 0.8.5 has no second binary; patching is a mode of jdiff (`-u`), a library class (JPatcht), and an argv[0] alias (`jpatch`)**. A Rust `jptch` can be kept as a thin argv-presence wrapper around the library, but the 1:1 target semantics are `jdiff -u` + argv[0]=`jpatch` dispatch.
- Empirical: `jdiff -u` applies 0.8.1-generated patches correctly (§Part 2.3c). 0.8.1 `jptch` **cannot** apply 0.8.5 patches (§Part 2.3b).

## C. Wire format (patch byte format)

### C.6 JOutBin 0.8.1 vs 0.8.5 — THE FORMAT CHANGED

Byte-identical parts:
- Opcode/ESC constants (85:JDefs.h:163-168 == 81:JDefs.h:127-132): `ESC 0xA7, MOD 0xA6, INS 0xA5, DEL 0xA4, EQL 0xA3, BKT 0xA2`.
- `ufPutLen` length tiers — line-for-line identical (85:JOutBin.cpp:65-104 vs 81:JOutBin.cpp:64-103): 1..252→`len-1` (1B); 253..508→`252,len-253` (2B); 509..65535→`253,hi,lo` (3B); ≤0xFFFFFFFF→`254,b32..b0` (5B); >0xFFFFFFFF→`255,8B` (9B, only `#ifdef JDIFF_LARGEFILE`; 0.8.5's default Makefile does NOT define it — on a default 0.8.5 build, lengths >4GiB fall into the 5-byte form).
- ESC data-escaping in `ufPutByt`: pending-ESC + next byte in `BKT..ESC` (0xA2–0xA7) → extra ESC (85:JOutBin.cpp:136-160 == 81:129-147).

**Change 1 — implicit MOD ("default ops", v083p, 85:main.cpp:129).**
`ufPutOpr` now emits `ESC <opr>` only when `aiOpr != MOD || miOprCur == INS` (85:JOutBin.cpp:121-128);
0.8.1 always emitted it (81:JOutBin.cpp:118-123). The constructor seeds `miOprCur(MOD)` (85:27)
instead of 0.8.1's `miOprCur(ESC)` (81:26). Net effect: a MOD run at the very start of the patch, or
following EQL/DEL/BKT, is emitted **without** the `ESC MOD` prefix; the reader (JPatcht) defaults the
operator to MOD when it reads a non-ESC byte at operator position (85:JPatcht.cpp:252-254, "If an ESC
<opr> is missing, set default operator (gaining two bytes)"). `ESC MOD` is still emitted when switching
INS→MOD.

**Change 2 — short-EQL threshold: 4 → `MINEQL`(=2).**
New constant 85:JOutBin.h:28 `#define MINEQL 2    // start EQL-sequence on 3'rd byte`.
Pending-equal flush: `if (mzEqlCnt > MINEQL || (miOprCur != MOD && aiOpr != MOD))` → EQL (85:JOutBin.cpp:175)
vs 0.8.1's `mzEqlCnt > 4 || ...` (81:162); buffering `miEqlBuf[MINEQL]` with `mzEqlCnt < MINEQL` (85:221-223)
vs `< 4` (81:214-216). Net: runs of ≥3 equal bytes become `ESC EQL len`; 0.8.1 needed ≥5. (Runs of ≤2
between MOD runs are still emitted as MOD data.)

Empirical proof (§Part 2.3a, hexdumps): 0.8.1 patch starts `a7 a3 18 | a7 a6 | "MODIFIED"` (131 B);
0.8.5 patch starts `a7 a3 18 | "MODIFIED"` (127 B) — exactly the two dropped `ESC MOD` pairs.

**Compatibility verdict:** 0.8.5 patches are **not** readable by 0.8.1 jpatch (it drops leading non-ESC
bytes — 81:jpatch.cpp:129 `liOpr = ESC` with no MOD default, so implicit-MOD data bytes hit no case and
are discarded). 0.8.5's JPatcht reads **all** 0.8.1 patches (explicit opcodes are a subset of the grammar)
plus `ESC <same-opr>` inside a run (handled as data, 85:JPatcht.cpp:176-185 — the case the francisdb port
got flagged for in spec §15.7 is now upstream behavior). Verified live both directions (§Part 2.3).

Also unchanged: `put()` return-true protocol for long EQL runs; ESC flush semantics in `ufPutOpr`
(pending data-ESC → `ESC ESC`, 85:113-119 == 81:110-116). 0.8.5 moved the `miOprCur` bookkeeping inside
`ufPutOpr` (85:129) — same observable behavior.

## D. CLI surface & exit codes

### D.8 Option map — 0.8.5 (getopt_long) vs 0.8.1 (manual scan)

0.8.5 parses with `getopt_long`, short optstring `"a:bcd:fhi:jk:lm:n:pqrst::uvx:y"` (85:main.cpp:236) and
long options table (85:238-261). GNU permutation applies — options may appear **after** filenames

### D.10 stdin / stdout / sequential files

- **`-` filenames**: either input, and the output, may be `-` (85:main.cpp:268,612-615,758). Both inputs
  `-` → error exit 2 (85:612-615). Output `-` → stdout (85:759).
- **stdin plumbing**: without `-s`, stdin is wrapped in `JFileAheadIStream(cin, ...)` (85:715,733); with
  `-s`, `JFileAheadStdio(stdin, ...)` (85:671,689). Windows does `setmode(O_BINARY)` (85:664-668).
- **Sequential semantics** ("083v Sequential files"): a `JFile` is sequential if flagged so (`-p`/`-q`) or
  auto-detected: `chkSeq()` tries `jeofpos()` (seek END) and marks the file sequential on failure
  (85:JFile.cpp:37-46) — a pipe fails the seek, a regular-file redirect does not. Sequential inputs get
  bigger default buffers (org 32 MB, new 16 MB, 85:618-619) and main then force-applies the `-p`/`-q`
  behavior with the warnings quoted in A.2.4 (85:781-795).
- In `JFileAhead::get_fromfile`, sequential mode changes buffer refill: reading **before** the buffer is
  EOB (soft) / SeekError (read) / EOB (hard) (85:277-292); Reset seeks forward keeping the tail
  (`mzPosInp = ((azPos - mlBufSze + miBlkSze)/miBlkSze)*miBlkSze`, 85:316); SoftAhead append is bounded by
  `mzPosBse + mlBufSze - miBlkSze` (85:303-304).
- Verified live: `cat new | jdiff org - > p` (auto `-q` warning, 127-byte patch, round-trips); `cat org |
  jdiff -p - new` (round-trips); `cat patch | jdiff -u org -` restores. All in §Part 2.4.

### E.11 JMatchTable rework — dynamic matching table

0.8.1 (81:JMatchTable.h:29-30, 81:JMatchTable.cpp:60-85): fixed pool `msMch = malloc(MCH_MAX=256)`,
freelist via `ipNxt`, **127** buckets (`MCH_PME`) keyed on `delta=fndOrg-fndNew` with `idx<0 → -idx`
(−δ and +δ share a bucket), single "last gliding match" pointer (`mpMchGld`+`mzGldDlt`,
81:116-126), `get()` walks **all 127 buckets** (81:210), `check()` hunts a run of `SMPSZE-8` equal
bytes returning 0/1/2 (81:405-459), repairs counted in **static** `siHshRpr` (81:58).

0.8.5 (85:JMatchTable.cpp:78-105): the table size is the `-x` value (`miMchSze = max(13, aiMchSze)`,
85:85 — NB: `miMchFre` is initialized from the *unclamped* `aiMchSze`, see NEW-QUIRK #1); **two** hash
tables both sized `miMchPme = getLowerPrime(aiMchSze*2)` (85:97-99): `mpCol` on `|delta| % miMchPme`
(85:197) and `mpGld` on `izOrg % miMchPme` (85:215) — so gliding detection became hash-based instead of
"last match only". Node `rMch` (85:106-119): `ipNxt` (aging list), `ipCol`, `ipGld`, `iiCnt`, `iiGld`
(gliding recurrence, 85:227-232), `izBeg/izNew/izOrg/izDlt/izTst`, `iiCmp` (compare result:
`CMPINV -1 / CMPSKP -2 / CMPEOB -3`, 85:49-51). Elements are **never freed** — they live on
`mpNew`/`mpOld` aging lists and are *reused* when `isOld2Reuse` says so (85:755-768); "full" means no
reusable old element (85:358-359). Best-match is now tracked incrementally (`mpBst/mzBstOrg/mzBstNew/
miBstCmp`) inside `isBest()` during `add`/`cleanup` (85:543-656) instead of a full table walk in `get()`.
`getbest()` (85:117-171) mostly just returns the tracked best (plus an EOB re-evaluation pass when
`!mbCmpAll`, 85:124-145). `HSH_RPR` fate: the 0.8.1 *global static* `JMatchTable::siHshRpr` is gone;
repairs are the instance counter `miHshRpr`, exposed as `getHshRpr()` (85:930-932), printed by main as
"Index table repairs" (85:851). `cleanup(bseOrg,redNew)` (85:373-438) joins lists, marks very old
elements `CMPSKP` via `isOld2Skip`, re-evaluates the rest, and returns Full/Invalid/Valid/Good/Best which
`JDiff::search` uses to shorten the lookahead (85:JDiff.cpp:495-508).

**Tuning constants (085ac "tuning internal parameters", commit 66a2806):** the commit did **not** change
the numeric `#define`s (EQLSZE/EQLMIN/EQLMAX/MAXDST/MINDST/FZY all pre-existed). What it changed
(verified via `git show 66a2806`): cached reliability into member `JDiff::miRlb` (refreshed after index
build / incremental scan, 85:JDiff.cpp:415,445) replacing per-use local `liRlb`; replaced the
`isOld2Skip`/`isOld2Reuse` aging thresholds `2*miRlb` → fixed `MAXDST` (2 MiB) bounds
(85:JMatchTable.cpp:733-768); `nextold()` now reactivates enlarged invalids instead of moving them
straight to the old list (85:683-700); `cleanup()` return-order simplified (85:426-437); equal-run
counting batched via `lzCnt` (85:JDiff.cpp:199-224); removed the debug-only "version lente" cleanup
variant; comment/doc churn.

Current constant set (85:JMatchTable.cpp:36-46):
```
#define EQLSZE 8        // Continuous runs of 8 (>7) equal bytes are worth the jump
#define EQLMIN 4
#define EQLMAX 256
#define MAXDST 2*1024*1024   // Max compare distance (HDD rationale comment)
#define MINDST 1024          // Min compare distance
#define MAXGLD 128           // Max distance for gliding matches  -- DEAD: no other reference in tree
```

vs 0.8.1's only constant `FZY=0` (81:JMatchTable.cpp:185) + implicit `SMPSZE-8` run length and
`rlb≥1024` floor (81:206-207). 0.8.1's `check()` two-phase (mismatch-tolerant phase then strict phase)
is replaced by a single loop with glide-aware realignment (`azPosOrg -= liEql` on mismatch when gliding,

### E.12 JHashPos changes

- **Units**: ctor arg is **MB**, converted to elements `aiSze*1024*1024/(sizeof(hkey)+sizeof(off_t))`
  (= `MB*65536` on LP64, 16 B/element) then `getLowerPrime` (85:JHashPos.cpp:48-60). 0.8.1 took an
  element count and picked from the fixed `giPme[20]` table (81:JHashPos.cpp:38-61). Consequence: actual
  primes differ (verified: default `-i 32` → **2097143** samples at 0.8.5; 0.8.1 default 8 Mi-elements →
  **8388593**).
- **Initialization**: 0.8.5 `malloc`s the table with **no memset** (85:65-67) — 0.8.1 `memset` to 0
  (81:78). Uninitialized-key reads in `get()` are possible on a fresh table (NEW-QUIRK #2; benign-ish on
  fresh-heap pages but a real determinism/UB divergence for a port).
- **Collision/add cadence**: counter now counts **down** from `miHshColMax` (start 4 = COLLISION_THRESHOLD)
  and stores when `<= 0`, resetting to `miHshColMax` (85:99-138); load counter counts down from
  `miHshPme`, and each wrap does `miHshColMax += 4; miHshRlb += 4` (85:104-110) — same cadence as 0.8.1's
  count-up (81:96-137) but inverted direction and reset point (0.8.1 reset colCnt to 0).
- **Quality gate**: `aiEqlCnt <= SMPSZE*2` → −4 (COLLISION_HIGH) else −1 (COLLISION_LOW) (85:116-119).
  Since 0.8.5's hash caps `aiEql` at `SMPSZE` (85:JDiff.cpp:361-370), the `else` branch is unreachable —
  every sample gets HIGH credit (NEW-QUIRK #3; 0.8.1 gate was `<= SMPSZE-4` with the weird possibly-negative
  `aiEql` from `ufFndAhdGet`'s `-= 2`, 81:JDiff.cpp:504-513).
- **Reliability seed**: `miHshRlb = SMPSZE + SMPSZE/2` (85:50) = 96 on LP64 (0.8.1 hardcoded 48, 81:56);
  `reset()` restores all of it (85:144-149) — `reset()` is never called anywhere at 0.8.5.
- `hkey` is still `unsigned long int` (LP64 ⇒ 64-bit, SMPSZE=64) — see §G.12.
- Counters/print: `get_hashhits/get_hashprime/get_hashsize/get_hashcolmax/get_reliability` kept;
  `print()` format unchanged (`Hash Pnt %12d P8zd-%08PRIhkeyx`, 85:176-185); `dist()` recomputed
  (`Overload = colMax/4 − 1` vs 0.8.1 `colMax/3`; `Avg/Min/Max/%` and `Load` formulas now guarded against
  div-by-zero and compute `(100 - liMin/(liMax/100))` and `liCnt/(miHshPme/100)`, 85:192-238). 0.8.1's
  dead `get_size_index` declaration is gone. The hash *function itself* moved to `JDiff::hash`
  (see E.14) — `JHashPos::hash` no longer exists.

### E.13 JFileAhead rework — incremental scanning, buffer state machine

New architecture (85:JFileAhead.cpp):
- Buffer state: `mpBuf/mpMax/mpInp` (circular write cursor), `miBufUsd`, `mzPosInp` (file offset of
  `mpInp`), `mzPosBse` (soft-lookahead base), plus base-class read cursor `mzPosRed/miRedSze/mpRed`
  (85:JFileAhead.h:159-170, 85:64-77). `getBufPos() = mzPosInp - miBufUsd` (85:102-104).
- `getbuf(pos,&len,eAhead)` (85:210-254): EOF if `pos >= mzPosEof`; in-buffer if
  `mzPosInp-miBufUsd <= pos < mzPosInp`; else `get_fromfile` whose result maps to
  `EndOfBuffer(EOB)/EndOfFile(EOF)/SeekError(EXI_SEK)/ReadError(EXI_RED)` (85:221-228). In-buffer pointer
  math with wraparound at 85:231-238.
- `get_fromfile` decision tree (85:269-307) — **the liSek quirk is FIXED**: the seek mode is now the enum
  `eBufOpr liSek` ∈ {Append, Reset, Scrollback} (85:114, 273):
  - `pos < mzPosInp - miBufUsd` (before buffer): SoftAhead → EOB; sequential: HardAhead → EOB, Read →
    **SeekError**; else **Scrollback** if `pos + mlBufSze - miBlkSze > mzPosInp - miBufUsd`, else Reset
    (85:277-292). (0.8.1's `bool liSek` collapsed mode 2→1 so scrollback never ran, spec §15.8.)
  - `pos >= mzPosInp + mlBufSze` (beyond a buffer): SoftAhead → EOB else Reset (85:293-300).
  - else Append, but SoftAhead returns EOB past `mzPosBse + mlBufSze - miBlkSze` (85:301-307).
  - Reset realigns to a block boundary (`(pos/blk)*blk`, or the sequential tail-preserving variant
    85:311-317), seeks (`mlFabSek++`), then `readblocks` fills up to `pos`. Scrollback (85:341-382)
    computes the block-aligned back position, makes room, seeks back, refills, then **seeks forward
    again** to `mzPosInp` (`mlFabSek++` twice), mapping a mid-scrollback EOF to `ReadError`.
  - `readblocks` (85:392-431): loop of `jread` in `blk`-sized (or buffer-remainder) chunks, maintaining
    `mpInp/mzPosInp/miBufUsd` with `miBufUsd` clamped to `mlBufSze`; short read sets `mzPosEof` and
    returns EOF when `azEnd >= mzPosEof`.
- **The 0.8.1 dead `lbFnd` check** lived in JDiff.cpp, not here — its fate is FIXED (E.14). The other
  0.8.1 JFileAhead oddities are gone with the rewrite: no more `Buffer out of bounds ... exit(6)` path
  (81:JFileAhead.cpp:326-331; 0.8.5 clamps and wraps instead), no partial-read recursion
  (`return get(azPos, aiTyp)` recursion replaced by the getbuf flow).
- Debug-build safety net (always-on in `-D_DEBUG` builds, not flag-gated): `getbuf` asserts invariants
  and calls `exit(-EXI_SEK)` on violation (85:240-251) — this is what fires in `-t` Test mode
  (`JFileAhead::getbuf(New,-1,1,0)-> ... failed !`, §Part 2.6). The `DBGRED` block (85:149-186)
  double-verifies buffer contents against the file with a 1 MiB static scratch buffer.
- "Incremental scanning" (085aw/085bl/085ac): when `srcScn==0` (`-ff`/`-p`), the source index is built
  *during* the main compare loop (85:JDiff.cpp:185-189) and inside equal-run fast loops
  (85:JDiff.cpp:201-214), plus a SoftAhead pre-scan of the source ahead of the read position bounded by
  `liMax` derived from `miAhdMax` and `mzAhdOrg` (85:JDiff.cpp:419-447). This replaces 0.8.1's
  `ufFndAhd` inline hash-both-files loop (81:JDiff.cpp:340-368, 381-396).

- **Hash function changed**: 0.8.1 `JHashPos::hash`: `key = key*2 + byte` (81:JHashPos.h:109-117), with

### E.15 JFileIStream fate

0.8.1's unbuffered `JFileIStream` was istringstream-based (the `-m 0` in-memory path, with the NUL
truncation and stale-failbit defects, spec §15.3/§15.10). 0.8.5's `JFileIStream` is a rewritten

binary level; the class survives as dead code with a *correct* failbit/eofbit handling pattern.

1. **`miMchFre` initialized from unclamped `aiMchSze`** — `miMchSze(aiMchSze<13?13:aiMchSze),

  the harness: for each consecutive file pair in `<dir>` (grouped by basename, extensions
  tar/fil/txt), runs jdiff over an option list, times it, greps the `Data/Equal/Control-Esc bytes` stat

  optional xdelta3 comparison; long/short option rotation; `-p` runs `cat org | jdiff - -` and `-q` runs

  `*.fil`, `tstA/B*.txt` the author had locally.
- `jlog.sh <logs>` — reformats jtst logs into a SIZE/TIME/DATA/OVH/EQL/ERR/OPTIONS table (greps
  `Data bytes`, `Control-Esc bytes`/`Overhead bytes`, `Equal bytes`, `JDF`/`ERR`/`user` lines).
- `jdst.sh <n>` — moves `c:/temp/jdiff.txt` and tallies `Hash Pnt` debug lines into a bucket histogram

`hsk/bkt/dst` have **no sites at all** in the source). Unknown `-d zzz` silently ignored.
