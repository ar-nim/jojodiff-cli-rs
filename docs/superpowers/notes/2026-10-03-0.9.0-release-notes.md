# jojodiff-cli-rs 0.9.0

Same JojoDiff 0.8.5 behavior — byte-identical patches, listings, verbose
output and exit codes — on an idiomatic-Rust internals refactor.

- **Breaking (library API):** `JFile::get` returns `ByteOrEof`; engine
  APIs return `Result<_, JDiffError>`; opcodes are the `Op` enum; the CLI
  lives in the `cli` module with `cli::run` as the testable entry point
  (`src/bin/jdiff.rs` is a 13-line `anyhow` wrapper).
- **Dependencies:** `thiserror` + `anyhow` replace the zero-dependency
  property (documented decision record in the refactor spec §13, mirrored
  in the README dependency table); `sysinfo` (default features off,
  `system` only) powers the memory guard's platform ceiling. Dev-only:
  `tempfile` (RAII scratch dirs), `assert_cmd` + `predicates` (CLI
  spawns), and the `jojodiff` 0.1.2 crate for oracle cross-validation.
  `pretty_assertions` was removed as unused.
- **Tests:** 235 green — in-process unit tests for parsing, sizing,
  dispatch and the error boundary; a `tempfile`/`assert_cmd` harness with
  RAII scratch dirs; byte-exact goldens; debug-build and release oracle
  jobs against the 0.1.2 reference crate.
- CLI behavior, the printed version banner, and goldens are unchanged;
  `--compat-081` patches and 0.8.1-era applicability are unaffected.

## Fixed

- Huge `-m`/`-x`/`-i`/`-k` values now exit 10 (`Error allocating memory !`)
  with a per-option memory breakdown instead of aborting; the check is
  bounded by the platform's available RAM + swap (queried via the
  `sysinfo` crate — `MemAvailable`+`SwapFree` semantics on Linux, mach
  estimates on macOS, free physical memory on Windows) and can be skipped with
  `JDIFF_UNSAFE_NO_MEMGUARD=1` (spec §21.19). `-i ≥ 2049` no longer
  overflows the table-size statistic (was negative garbage; debug builds
  panicked). `-f`×8 / `-b`×12 flag chains no longer panic in the matching
  table (floored to the same 1024 default as a non-positive `-x`).
